# Как продолжить с другим агентом или на другом компьютере

## Что сохранено

- `skills/telegram-channel-studio/SKILL.md` — общий навык создания и развития подобных каналов.
- В этой папке навыка: справочники по pipeline, Windows, переносу и текущему проекту, а также
  скрипт безопасного экспорта/установки навыка.
- `AGENTS.md` — входная точка для агента, открывшего папку проекта.
- `AGENT_HANDOFF.md` — архитектура, ресурсы, настройки без секретов, проверки и известные ограничения.
- `ADMIN.md` и `OPERATIONS.md` — эксплуатация и десктопная админка.
- `portable` — подготовленные ZIP-архивы. Это локальные переносимые копии, они исключены из Git.

Проектная копия навыка — основная. При развитии навыка обновляйте также установленную копию,
если хотите, чтобы другие чаты автоматически находили новую версию.

## Другой логин агента на этом компьютере

Откройте папку `C:\Projects\DotNetChannel` и дайте агенту такой запрос:

> Прочитай AGENTS.md, AGENT_HANDOFF.md и skills/telegram-channel-studio/SKILL.md в этой папке.
> Продолжи текущий проект. Сначала проверь реальное состояние сервиса и очередь; не создавай
> заново бота или канал. Моя задача: [опишите изменение].

Навык можно читать напрямую из проекта независимо от аккаунта агента. Для установки в локальный
каталог навыков этого компьютера выполните из папки проекта:

```powershell
python skills/telegram-channel-studio/scripts/project_transfer.py install-skill
```

Копия появится в `CODEX_HOME\skills\telegram-channel-studio` или, если переменная не задана,
в `%USERPROFILE%\.codex\skills\telegram-channel-studio`. Если там уже лежит отличающаяся версия,
скрипт откажется перезаписывать её. Возможно, потребуется новый чат/перезапуск приложения для
обновления списка навыков. Прямое чтение проектного SKILL.md работает и без установки.

## Новый компьютер: продолжить существующий канал

1. Перенесите архив `portable\DotNetChannel-transfer.zip` и распакуйте в удобную папку Windows.
   Он содержит исходники, навык и согласованный снимок SQLite, но не содержит ключей/токенов.
2. Установите .NET SDK 10, совместимый с текущими target frameworks. Python 3.10+ нужен только
   для helper-скрипта экспорта/установки навыка; сам сервис и админка работают на .NET.
3. Если нет `settings.local.json`, скопируйте `settings.transfer.json` под этим именем.
   Восстановите BotToken существующего бота и свой AdminUserId локально. Для API задайте
   OPENAI_API_KEY или OpenAiKey. Ключи переносите отдельно выбранным вами способом, не в чате.
4. **Перед запуском на новом компьютере остановите старый worker.** Один токен бота не должен
   одновременно обслуживаться двумя экземплярами, даже с разными копиями базы.
5. Сохраните перенесённую `data\channel.db`: она содержит историю и защиту от повторов.
   Сборка и безопасные проверки из новой папки:

```powershell
dotnet build DotNetChannel.sln -c Release
dotnet test tests/Channel.Tests/Channel.Tests.csproj -c Release
dotnet run --project src/Channel.Worker -- --preview
dotnet run --project src/Channel.Worker -- --check
```

6. Попросите агента создать задачу Windows и ярлыки заново с фактическим путём и текущим
   Windows-пользователем. `install-autostart.ps1` — пример настройки; если политика подписи не
   позволяет запускать скрипты, агент может зарегистрировать задачу поддерживаемым API без
   изменения политики безопасности. Действие задачи — native `Channel.Launcher.exe`, не PowerShell.
7. В transfer-конфигурации специально выставлено `AutoPublish: false`. Выберите нужный режим
   и запускайте только после проверки адреса канала, токена и владельца. Не генерируйте пробный
   пост, если достаточно проверить существующую интеграцию без повторной публикации.

Токены, пользовательские переменные окружения, Windows-задачи, бинарники, журналы, runtime/PID
и абсолютные ярлыки в архив не входят. Их нужно восстановить/собрать на месте.

Снимок может включать незавершённую отправку. После восстановления сервис пометит её как
неопределённую; проверьте канал перед повтором. Состояние «был запущен» не переносится: решайте
о запуске по текущей задаче, а не по старому скриншоту.

## Создать новый похожий канал

Передайте другому агенту папку навыка либо архив `portable\telegram-channel-studio.zip`.
Для примера исходников есть `portable\DotNetChannel-source.zip` без очереди старого канала.

Запрос:

> Используй $telegram-channel-studio из skills/telegram-channel-studio/SKILL.md.
> Создай отдельный похожий проект для [источник], аудитория [кто], канал [новый/имеющийся].
> Нужны автоматическая переработка, публикация и десктопная админка.

Новый канал должен получить собственную конфигурацию, базу, бота/назначение и задачу Windows.
Не копируйте старую publication metadata в базу нового назначения. Часть названий задачи и
ссылок текущего проекта пока задана константами — агенту нужно их адаптировать.

## Обновить архив после дальнейших изменений

Выберите новое имя архива: существующий файл helper не перезаписывает.

```powershell
python skills/telegram-channel-studio/scripts/project_transfer.py export --project . --output portable/next-transfer.zip --include-state
python skills/telegram-channel-studio/scripts/project_transfer.py export --project . --output portable/next-source.zip
```

Экспорт использует SQLite backup API, включает committed WAL-данные и не останавливает сервис.
TRANSFER-MANIFEST.json содержит список файлов и SHA-256. Скрипт использует allowlist исходников,
не экспортирует локальную конфигурацию и проверяет содержимое на известные секреты и типичные
шаблоны ключей. Проверка не заменяет просмотр новых файлов перед публичным распространением.
Архив с базой содержит рабочую историю; не публикуйте его как общедоступный шаблон.
