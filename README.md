# DotNetChannel

Сервис на .NET 10: публичный Telegram-канал → упрощение через OpenAI → черновик в личном чате → публикация в вашем канале. Источник по умолчанию: https://t.me/NetDeveloperDiary.

Первая версия работает с текстовыми постами и кодом. Авторизация вашим Telegram-аккаунтом, api_id и api_hash не требуются. Никакие сообщения в донорский канал не отправляются.

## 1. Создайте своего бота

1. В Telegram откройте официального https://t.me/BotFather.
2. Отправьте `/newbot`.
3. Задайте отображаемое имя, например «Понятный .NET — редактор».
4. Задайте свободный username, заканчивающийся на `bot`.
5. BotFather выдаст токен. Сохраните его локально в `settings.local.json`, поле `BotToken`.
6. Откройте созданного бота по ссылке от BotFather и нажмите Start.

Используйте отдельного бота для проекта: другой запущенный сервис, webhook или второй getUpdates будут мешать получению команд. Токен позволяет управлять ботом, поэтому не отправляйте его в чат и не коммитьте в Git. При утечке перевыпустите его через BotFather.

## 2. Создайте канал назначения

1. В Telegram выберите «Создать канал».
2. Укажите название и описание. Для первого запуска проще создать публичный канал с username.
3. Откройте управление каналом → Администраторы → Добавить администратора.
4. Выберите своего бота и разрешите «Публикация сообщений».
5. Запишите `@username_вашего_канала` в поле `TargetChannel`.

Это адрес ВАШЕГО канала. `SourceChannel` уже содержит `NetDeveloperDiary`, его менять не нужно.
Приватный канал также поддерживается: вместо username потребуется его числовой chat ID, обычно вида `-100...`. Для первой настройки используйте публичный канал, чтобы не искать этот ID отдельно.

## 3. Узнайте свой Telegram ID

Файл `settings.local.json` уже создан с пустыми секретами. Если переносите проект на другую машину, скопируйте `settings.example.json` под именем `settings.local.json`.

После заполнения `BotToken` откройте PowerShell:

```powershell
cd C:\Projects\DotNetChannel
dotnet run --project src/Channel.Worker -- --setup
```

Отправьте своему боту `/start`. Консоль покажет ID и username отправителя и завершится. Убедитесь, что username ваш; если показано старое чужое сообщение, повторите команду после очистки очереди либо дождитесь своего сообщения. Запишите свой числовой ID без кавычек в `AdminUserId`. Сервис принимает управляющие команды и кнопки только от этого пользователя в его личном чате с ботом.

## 4. Получите ключ OpenAI API

1. Откройте https://platform.openai.com/ и войдите в свой аккаунт.
2. В настройках проекта откройте API keys: https://platform.openai.com/api-keys.
3. Создайте секретный API-ключ и сохраните его в поле `OpenAiKey`.
4. В Billing проверьте доступность оплаты/кредитов API для своего аккаунта.
5. В Usage / Limits задайте доступные ограничения расходов и уведомления. Приложение дополнительно ограничивает число попыток генерации, но это не денежный лимит.
6. В `Model` укажите `gpt-5.2` для первого запуска, если модель доступна вашему проекту. Можно использовать другую модель с поддержкой Responses API и Structured Outputs.

Наличие подписки ChatGPT само по себе не подтверждает доступность API для вашего проекта. Проверяйте API Billing и доступные кредиты в кабинете. Ключ вводится только локально; присылать его в чат не нужно.

## 5. Заполните конфигурацию

Пример значений (идентификаторы и ключи здесь вымышлены):

```json
{
  "SourceChannel": "NetDeveloperDiary",
  "BotToken": "ВСТАВЬТЕ_ТОКЕН_ОТ_BOTFATHER",
  "AdminUserId": 123456789,
  "TargetChannel": "@my_dotnet_channel",
  "OpenAiKey": "ВСТАВЬТЕ_КЛЮЧ_OPENAI",
  "Model": "gpt-5.2",
  "PollSeconds": 120,
  "MaxDraftsPerDay": 3,
  "AutoPublish": false,
  "DataDirectory": "data",
  "PromptFile": "prompts/rewrite.txt"
}
```

Сохраняйте корректный JSON: двойные кавычки, без комментариев и без запятой после последнего поля. `AdminUserId` — число, `AutoPublish` — true/false без кавычек.

Вместо секретов в файле можно задать переменные окружения `CHANNEL_BOT_TOKEN` и `OPENAI_API_KEY`; они имеют приоритет над файлом. Модель можно переопределить через `CHANNEL_AI_MODEL`.

`MaxDraftsPerDay` — максимум попыток обращения к ИИ за календарные сутки UTC, включая отказы, ошибки и переработки. Необработанные посты остаются в очереди. Смена суток по Киеву и UTC происходит в разное время. Для начала оставьте 3.

## 6. Проверьте и запустите

Проверка чтения донора без ключей, расходов и отправки сообщений:

```powershell
dotnet run --project src/Channel.Worker -- --preview
```

Проверка Telegram, прав бота и доступности личного чата (без публикации и без вызова ИИ):

```powershell
dotnet run --project src/Channel.Worker -- --check
```

Пробная обработка последнего поста и дальнейшая работа сервиса:

```powershell
dotnet run --project src/Channel.Worker -- --draft-latest
```

Дождитесь сообщения бота. Это первый реальный платный вызов ИИ. Прочитайте замечания и черновик; кнопки под ним позволяют опубликовать, переработать или пропустить. Код будет оформлен моноширинным блоком. В публикацию добавляется ссылка на пост-донор.

Если последний пост не технический, ИИ может пропустить его. Состояние видно через `/status`; сервис продолжит ждать следующие посты. Повторный запуск `--draft-latest` не создаёт копию уже существующего поста.

Обычный запуск:

```powershell
dotnet run --project src/Channel.Worker
```

При самом первом обычном запуске сервис запоминает последний пост и ждёт новые — старый архив целиком не обрабатывается. Пока вы проверяете черновики, новые посты продолжают попадать в очередь. Интервал проверки приблизительный: длительность вызова ИИ и Telegram long polling может его увеличить. Остановка: Ctrl+C.

Альтернатива длинным командам: `./start.ps1 -Mode preview`, `setup`, `check`, `draft-latest`, `status` или `run`. Если политика PowerShell блокирует скрипт, используйте приведённые выше команды dotnet; менять системную политику не требуется.

## 7. Включите полностью автоматическую публикацию

Сначала оцените несколько реальных черновиков. Затем остановите сервис, измените `AutoPublish` на `true` и запустите снова. Новые подходящие посты после обработки будут сразу отправляться в канал без кнопки подтверждения. Существующие черновики в состоянии `Review` остаются на ручной проверке.

Расписания на определённые часы в этой версии нет: публикация происходит после обработки, в пределах дневного лимита попыток. Чтобы вернуть проверку, остановите сервис и установите `AutoPublish: false`.

## Команды и ошибки

- `/status` — состояния очереди и последние ошибки.
- `/retry 3390` — вернуть пост с ошибкой `Failed` в очередь обработки. Учитывается дневной лимит.
- `/resolve 3390 published` — подтвердить, что пост с неопределённым результатом уже есть в вашем канале.
- `/resolve 3390 retry` — только после ручной проверки вернуть его на отправку. При `AutoPublish: true` отправка произойдёт автоматически; при false придёт новый черновик с кнопками.
- Локально при остановленном сервисе: `dotnet run --project src/Channel.Worker -- --status`.

При сетевом сбое во время отправки нельзя достоверно узнать, принял ли Telegram пост. Сервис ставит `Uncertain` и не повторяет отправку сам. Откройте свой канал, проверьте наличие публикации и используйте соответствующую команду `/resolve`. При прерванной отправке черновика также используется `Uncertain`; если публикации не было, выберите retry. После перезапуска проверьте `/status`.

Нажатие на старую кнопку, повторное нажатие и команды от другого аккаунта не приводят к повторной публикации. Запуск двух экземпляров с одной папкой данных блокируется. Не подключайте один бот к нескольким экземплярам даже с разными папками данных.

OpenAI HTTP 401: проверьте ключ. HTTP 403: доступ/регион/права проекта. HTTP 429: баланс или лимиты. HTTP 400: модель либо поддержка параметров запроса. Подробные ответы с возможными исходными данными не печатаются в лог. После исправления используйте `/retry ID`.

## Где менять алгоритм

`prompts/rewrite.txt` — аудитория, тон, структура, отбор тем, ограничения и требования к точности. Файл перечитывается при каждой генерации. Схема JSON задана в коде; сохраняйте поля relevant/text/reviewNotes.

Это самопроверка той же модели, а не независимый фактчекинг. Код из постов не запускается. Внешние статьи по ссылкам не скачиваются: ИИ получает только текст Telegram-поста и список ссылок. Посты, состоящие из одного анонса, должны отклоняться как недостаточные. Картинки, видео, файлы, альбомы и редактирование уже полученных постов не обрабатываются.

## Постоянная работа

Для локальной пробы достаточно этого компьютера с запущенным процессом. При закрытии программы, выключении или сне компьютера работа прекращается.

Для постоянной работы перенесите проект на сервер с Docker, заполните `settings.local.json`, затем:

```text
docker compose up -d --build
docker compose logs -f --tail 100
docker compose down
```

Публичный IP, домен и входящие порты не нужны: все соединения исходящие. Нужен исходящий HTTPS-доступ к t.me, api.telegram.org и api.openai.com. Docker на текущем компьютере не требуется для локального запуска.

Папка `data` содержит оригиналы, черновики, состояния и служебные отметки в SQLite. Для резервной копии остановите сервис и скопируйте всю папку `data` вместе с конфигурацией. Не удаляйте базу при обычном перезапуске: она защищает от повторов. При смене донора, бота или канала назначения используйте отдельную папку DataDirectory, чтобы не смешивать очередь и отметки.

Публичная веб-страница Telegram не является стабильным API. При изменении разметки чтение может потребовать обновления. После простоя сервис пытается прочитать до 20 предыдущих страниц; при большем разрыве останавливает продвижение отметки и пишет ошибку. Удалённые до чтения посты, недоступные веб-публикации и история за пределами этого окна не гарантируются.

## Структура и проверки

```text
DotNetChannel.sln
src/Channel.Core             — модели и ограничения публикаций
src/Channel.Infrastructure   — Telegram, OpenAI, SQLite, HTML-парсер
src/Channel.Worker           — очередь и обработка команд
tests/Channel.Tests          — проверки защиты от дублей и ошибок
prompts/rewrite.txt          — правила редактора
settings.local.json         — ваши настройки (исключён из Git/Docker build)
```

```powershell
dotnet build DotNetChannel.sln -c Release
dotnet test DotNetChannel.sln -c Release
```

Библиотеки: HtmlAgilityPack и Microsoft.Data.Sqlite. Вызовы Telegram/OpenAI выполняются через HttpClient. Пользовательские тексты отправляются в выбранный API для обработки. Ссылку на источник сервис добавляет автоматически; условия использования материалов источника следует согласовать для вашего формата канала.

Официальная документация, использованная при реализации:

- Telegram Bot API: https://core.telegram.org/bots/api
- Создание бота: https://core.telegram.org/bots/tutorial#obtain-your-bot-token
- OpenAI Responses / генерация: https://developers.openai.com/api/docs/guides/text
- Модель для первого запуска: https://developers.openai.com/api/docs/models/gpt-5.2

Проверено локально: сборка, автоматические тесты и получение реального текста канала. Реальная генерация, доставка черновика, публикация и фоновая работа также проверены; см. OPERATIONS.md.
