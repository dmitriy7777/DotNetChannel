# Десктопная админка

Запуск: ярлык **DotNetChannel Admin** на рабочем столе или такой же ярлык в `C:\Projects\DotNetChannel`.

Исполняемый файл: `src\Channel.Admin\bin\Release\net10.0-windows\Channel.Admin.exe`.
Проект WPF включён в `DotNetChannel.sln`.

## Управление

- **Запустить / F6** — запускает существующую задачу Windows `DotNetChannel`.
- **Остановить / F7** — просит сервис отменить запросы, сохранить состояние и завершиться. Автозапуск при следующем входе в Windows остаётся включённым.
- **Перезапуск / F8** — штатная остановка и новый запуск.
- **Обновить / F5** — перечитать данные немедленно. Обычно интерфейс обновляется сам каждые 3 секунды.

Закрытие админки не останавливает сервис. Если процесс не завершился за 15 секунд, приложение сообщает об этом и не убивает его принудительно. При остановке во время отправки результат может остаться неопределённым; такую публикацию сервис не повторяет автоматически.

## Что показывается

- Наличие процесса, PID, время работы, состояние задачи Windows и автозапуск.
- Время последнего успешного чтения донора, ошибка источника и свежесть сигнала процесса. Старый сигнал помечается отдельно.
- Число опубликованных материалов, очередь, согласование и ошибки.
- Попытки вызова ИИ за текущие сутки UTC относительно лимита. Это не денежные расходы и не число успешных публикаций.
- Таблица постов с поиском по теме/ID и фильтрами состояния.
- Исходный текст, результат переработки, версия, замечания ИИ и ошибка выбранного поста.
- Ссылки на оригинал и на уже опубликованный пост.
- Донор, канал, модель ИИ, режим публикации, интервал чтения и номер последнего полученного поста.
- Данные Telegram: название и количество участников, включая бота. Они запрашиваются при открытии окна и по кнопке «Обновить данные Telegram»; рядом показано время запроса.
- Последние записи журналов stdout/stderr и ошибки запуска.

Просмотр базы работает в режиме read-only. Очередь меняется только по явному нажатию «Добавить в очередь» в разделе архива; при открытии окна новые посты не создаются. Токены и ключи в интерфейсе не показываются. Секреты из конфигурации дополнительно скрываются в отображаемых журналах.

Для изменения алгоритма есть кнопка «Правила переработки», открывающая файл в Блокноте. Модель и режим задаются в `settings.local.json`; после их изменения нужен перезапуск сервиса.

Сервис и окно работают на этом компьютере. Для фоновой обработки он должен оставаться включённым, без сна и с интернетом.

Проверено: сборка без предупреждений, 31 автоматический тест, штатная остановка/запуск/перезапуск из админки, закрытие окна без остановки сервиса и чтение реальных данных канала.

## Архив источника

На вкладке «Архив источника» можно выбрать период с датами (обе даты включаются, время Киев)
или последние N текстовых постов (1–1000). Кнопки «3 дня», «7 дней» и «30 дней» быстро задают период.
Нажмите «Сканировать»: это читает только публичные страницы, не вызывает ИИ и не публикует.
Сканирование можно отменить. За один проход читается максимум 50 страниц; если период прочитан
не целиком, интерфейс сообщает об этом. Медиа без текста в число текстовых постов не входят.

В таблице видны дата, ID, тема и отметка «Уже учтён» для всех известных ID, включая опубликованные,
пропущенные, ошибочные и ожидающие обработки. Их нельзя добавить повторно. Отметьте нужные новые
посты и нажмите «Добавить в очередь». ИИ затем отбирает технические статьи, пропускает рекламу,
вакансии и анонсы, перерабатывает материал и использует текущий режим публикации.
Отбор ИИ, как и переработка, расходует общий дневной лимит попыток.

Если сервис остановлен, очередь сохранится до нажатия «Запустить». При исчерпанном лимите
она продолжит обрабатываться в следующие сутки UTC. Граница автоматического чтения новых
публикаций (cursor) при работе с архивом не меняется.
## Language / язык интерфейса

По умолчанию интерфейс английский. Справа вверху есть переключатель English / Русский;
Ctrl+Shift+L переключает язык без перезапуска. Выбор сохраняется в data/admin.preferences.json.
Язык интерфейса не меняет язык статей, оригиналы, замечания ИИ или исходные записи журналов.
Переводы встроены из src/Channel.Infrastructure/Localization/en.json; русские строки — исходные
ключи, WPF использует DynamicResource. Новые языки требуют добавления каталога и пункта выбора.

## Tokens / токены

В таблице Posts есть колонка Tokens, а у выбранной статьи — вкладка Tokens с входными,
выходными, суммарными, кэшированными и reasoning-токенами. Учитываются все записанные попытки
статьи, включая переработки. Кэш и рассуждения являются подмножествами input/output и повторно
не прибавляются. Расход берётся из usage ответа OpenAI, а не из длины текста или оценок.

Раздел Usage & limits показывает записанный расход за сутки UTC/всё время, оставшиеся попытки
ИИ и, когда API сообщил, остаток окна скорости по последнему ответу с временем замера.
Это не баланс оплаты OpenAI. По выбору пользователя токенный бюджет не задан; значение остатка
такого бюджета — Not set. Для счёта OpenAI есть отдельная кнопка Open OpenAI Usage.

Учёт начинается с этой версии. У старых статей и ответов без usage расход неизвестен:
интерфейс показывает Not recorded/тире, а не выдуманный ноль. Неполные итоги отмечаются плюсом
и предупреждением о запросах без учёта. Уже опубликованную статью ради заполнения статистики
повторно обрабатывать не нужно.

SQLite ai_usage хранит попытку до вызова API и обновляет её фактическими usage-данными до
проверки результата генерации: даже incomplete или невалидный текст не теряет измеренный расход.
Если ответ не пришёл, расход остаётся неизвестным. Response ID, модель, ревизия и дата сохраняются;
токены бота и API-ключи в этой таблице не хранятся.
